# Sigma 1.1.5 patch ABI and memory design

Target remains Sigma 1.1.5 BETA. This report supplies implementation locations and constraints; it does not establish device-side acceptance or hardware operation.

All addresses below refer to `work/sigma/1.1.5/sigma-decoded.bin`, SHA-256 `03083142e185dbf9598b235281fff4608145f75628b8c7b51d2de642fad51622`. File offset = VA − `0x08020000`. Supporting bytes/instruction listings are in `work/sigma/patch-design/hook-evidence.json`, generated by `scripts/HookEvidence.py`. Decompilation is retained in `hooks.c` and `runtime.c` in that directory. A separate copied Ghidra project `sigma-hook.gpr` was used.

## RAM reservation established from startup

`0x080202AC` loads four values and returns through LR. Its bytes are `04 48 05 49 05 4A 06 4B 70 47`; the associated literals are:

| File offset | Register / role | Original value |
| --- | --- | --- |
| `0x2C0` | r0, heap base | `0x20004590` |
| `0x2C4` | r1, stack top | `0x20006590` |
| `0x2C8` | r2, heap limit | `0x20005590` |
| `0x2CC` | r3, stack base | `0x20005590` |

The routine is called at `0x08020462`. Startup then sets SP to aligned r1. At `0x08020270`, r2 is moved into r1 before the runtime argument/constructor path. The bounded bump allocator at `0x08020666` receives an arena with current pointer and limit, rounds an allocation to 4 bytes, rejects a size exceeding the remaining range, advances to an 8-byte boundary, and returns the prior current pointer. Calls in `0x08020688` use this for runtime argument buffers. `0x080465F4` is **FPU initialization**, not a heap allocator.

For an experimental patch, reserve **`[0x20005490,0x20005590)`**, 256 bytes, by changing only the heap-limit literal at file `0x2C8` from `90 55 00 20` to `90 54 00 20`. Preserve the separate stack-base literal at `0x2CC`, the stack-top literal and the initial vector SP. This reduces the declared heap from 4096 to 3840 bytes and does not extend the declared RAM range or reduce stack space. It is preferable to assuming spare memory outside the original allocation. No general malloc ABI has been established or is needed for this design.

Startup scatterload records at file `0x2DFF0` and `0x2E000` establish:

- Decompress source `0x0804E018` into `0x20000000`, output length `0x7B0`, using `0x080201D4`.
- Zero destination `0x200007B0`, length `0x5DE0`, using `0x08020230`. End is `0x20006590`, including the reserved patch state.

The instruction-equivalent decompressor consumes source file range `[0x2E018,0x2E26A)` and produces `work/sigma/patch-design/initial-data.bin`, 1968 bytes. Its exact hash and transformation range are recorded in `hook-evidence.json`. This is a useful emulator RAM initializer. The candidate should explicitly clear its own state again before constructing the added driver. Confidence: high for startup ranges and proposed reservation; physical capacity beyond these existing ranges remains unknown.

## Driver construction and vtables

Constructor chain `0x080250EC` initializes the host, hub, base, pedals, handbrake and shifter. The final call at **`0x08025102`**, bytes **`00 F0 21 F8`**, calls `0x08025148` (which constructs the shifter). Replace that four-byte BL with a BL to an appended wrapper. The wrapper must call the original `0x08025149` Thumb entry first, then zero the reserved state and call **`0x08025189(state, 0x20000820)`**. The constructor returns the state pointer in r0 even though Ghidra inferred `void`.

`0x08025188` invokes generic constructor `0x08024818`, which registers the object through `0x08023AF0` into the 16-slot host table at `host+0x78`. The existing startup occupies five slots: hub plus four application classes. The new class therefore uses the next empty slot. The constructor's base object occupies through byte `0x73`; use a **0x78-byte object prefix** before new private state. Existing peripheral classes sometimes use `+0x74` as a callback, but the generic object does not require that callback to be nonzero.

The generic vtable starting at `0x08046750` occupies 0x44 bytes of primary slots, followed by a −4 secondary-base adjustment and a secondary table. Copy the complete **0x50-byte region** into immutable patch ROM. Set object `+0` to the copy's beginning and object `+4` to the copy's **`+0x4C`**. Do not set the secondary pointer to the −4 word or to the primary table.

For report callback `+0x40`, the fifth argument is on the stack under AAPCS. The `has_report_ids` bit must not be assumed to remove the leading ID: the generic poll path passes the raw received buffer. Preserve Thumb low bits on all function pointers. Confidence: high, from call sites and copied tables.

Key object fields are host pointer `+8`; USB address u8 `+0x0C`; interface count u8 `+0x30`; endpoint count u8 `+0x31`; next deadline u32 `+0x34`; interval u8 `+0x38`; poll-enabled flag `+0x39`; report-ID flag `+0x6F`; PID u16 `+0x70`; VID u16 `+0x72`.

## Prevent accidental claims during enumeration fallback

Host enumeration has a pass that tries unmatched classes. A new VID/PID predicate alone is insufficient to prevent claiming another HID device.

Generic Init `0x08023BA0` stores VID/PID before extracting configuration endpoints. Its endpoint extractor `0x080241A8` invokes slot `+0x3C`. Replace that slot with a predicate that checks the stored identity is **3670:0804**, and restricts the expected interface/protocol if established from live descriptors. Returning zero for a different identity prevents installing endpoints. With endpoint count still one (the control endpoint), Init returns **`0xD1`** (signed −47, unsupported) before SET_CONFIGURATION. The on-init callback cannot reject the device: its return is ignored.

Also wrap Init to clean up a failed initial attempt. Capture whether the object was unbound (`+0x0C == 0`) before calling the original. If a new attempt fails after allocating an address, call the original release and clear private controls. Do not release an already bound device merely because Init returns **`0xD9`** (signed −39, busy). Some early unsupported paths return before the generic release path, so cleanup cannot be assumed.

Release `0x08023EC8` frees the object's USB address through the host, then resets endpoint count to one, address to zero, deadline to zero and poll-enabled to zero. A wrapper should clear the patch's pressed-control state and set the existing report-dirty byte so released controls propagate.

## Polling, timeout and report merge

Host loop `0x08022598`, called at main `0x08025318`, polls **all 16 populated registry slots** via vtable `+0x0C`, including unbound objects. A patch poll wrapper can therefore check disconnect/timeout state even when no new packet arrives. It should retain the original poll function's return value and preserve existing endpoint handling. The original interval derives from descriptors but is mutable; do not replace it with a guessed fixed USB interval.

The monotonic counter is returned by `0x0802503C` from RAM `0x2000081C`. A candidate timeout value is a design parameter pending measured hardware behavior, not an established protocol requirement. Use unsigned elapsed subtraction to tolerate wraparound.

Main gates report building on **u32 `0x20000D60 == 5`** and **u8 `0x20000000 != 0`**. The exact call to console report builder is **`0x0802537C`**, bytes **`05 F0 9A FA`**, target `0x0802A8B4`. Replace this four-byte BL with a wrapper that calls original Thumb entry `0x0802A8B5`, then merges patch controls into output buffer `0x20000C88`. No displaced instruction trampoline is needed when replacing the full BL instruction.

After this call, `0x0802A7EC` compares all 64 output bytes with the previous report at `0x20000CC8`. If different, `0x0802A7DC` triggers sending, main copies the new bytes to the previous buffer, and clears the dirty byte. New input, detach and timeout therefore need to set `0x20000000 = 1`. Hooking after the original builder preserves base steering and separate pedal/shifter/handbrake assembly and prevents subsequent base parsing from overwriting the Zeus contribution before this report is sent. Physical input→console mapping still requires its own evidence.

## ROM placement boundary

No large unused ROM code cave was established. The largest single-byte fill run is only 354 bytes and is within a data region, not proven disposable. Appending the patch after original image end **`0x0804E280`** avoids replacing existing code/data, other than the two reviewed BL sites and the heap-limit literal. The original image includes compressed initialization data and an unresolved final 16-byte region; preserve them at their original offsets.

The older 1.0.20 carrier is larger, but that alone does not prove that an enlarged 1.1.5 image will be accepted, written completely, or authenticated by the converter. Appended code is therefore an **offline experimental candidate** until the integrity and destination-size questions are resolved. No device writes were performed for this analysis.

## Initial implementation review

Reviewed `patch/sigma_zeus.c` SHA-256 `f2ac057813a3402472d9f109af5303cc03b3f33fcd1f8663ae5a7b808833716b`, `patch/zeus_profile.h` SHA-256 `2b68a420c1e78febc1506475366a1ad61da62d2bf5eddf8c7c0bd6dec13f9a52`, and linker script SHA-256 `085b8e985d3d61895fef22ed964e691078cf409939f31fe35db9e4751d58d447` against the evidence above. This identifies the reviewed snapshot; later edits need their own build/test hashes.

No definite ABI, object-offset or vtable-layout defect was found. The state struct is 156 bytes within the 256-byte reservation. The busy-object init path retains the existing binding. Failed first initialization frees an allocated address. Input, release and timeout paths update the existing report-dirty byte. The secondary vtable pointer correctly selects word 19.

The merge destinations independently agree with the console HID descriptor: input ID 1 payload bits 36–49 are 14 button bits (descriptor main item at file `0x26901`); payload bits 50–55 are vendor data (`0x2690C`); payload bits 56–71 are Rx/Ry (`0x2691D`). Including the report ID, the adapter's writes cover byte 5 high nibble, byte 6, byte 7 low two bits, and axes at bytes 8–9. Those writes preserve the hat nibble, vendor bits and independent steering/pedal fields. This validates byte placement, not physical control assignments or a game's interpretation.

Required emulator cases include actual constructor registration and secondary thunk, exact fifth-argument report delivery, wrong-identity fallback, failed initialization after address allocation, busy existing binding, report rejection, release, timeout/wraparound, and unchanged base/steering/pedal bytes. The initial 250-counter-tick timeout and development usage map are implementation choices pending capture; they are not protocol facts.
